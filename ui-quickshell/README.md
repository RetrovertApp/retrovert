# ui-quickshell

The Retrovert player's Omarchy interface: a Quickshell window that draws with the desktop's
own theme, with the frame-rate surfaces rendered natively into Qt's scene graph.

```
ui-quickshell/
  launcher/ the `retrovert-gui` binary users run: resolves paths, probes Vulkan, execs qs
  bridge/   Rust crate exporting a C ABI over crates/present; the only other crate allowed unsafe
  shim/     C++ QML module `Retrovert`: Session and Scope items over that ABI (CMake, Qt 6)
  ui/       shell.qml, Theme.qml, and symlinks to Omarchy's Commons and Ui component trees
  build.sh  cargo build of the bridge, then cmake of the shim into shim/build/qml/Retrovert
  run.sh    `cargo run -p retrovert-gui -- "$@"`, the dev shortcut for the launcher
```

Everything a renderer needs to decide lives in `crates/present`, which is plain Rust with no
Qt: scope polylines, and later VU decay, the pattern grid and theme tokens. Any other UI,
such as a flowi window, consumes the same crate. What is here is only the Omarchy binding.

## Decisions

**An application, not an Omarchy plugin.** Omarchy plugins load into the long-running
`omarchy-shell` process. A player with an audio engine and native rendering items would
crash the desktop bar with it, so Retrovert runs its own `qs` process, like Flea does, and
follows the theme by symlinking `/usr/share/omarchy/shell/Commons` and `Ui` into `ui/`.
A bar widget for now-playing can still be a plugin later, talking over MPRIS.

**A C ABI, no Rust Qt bindings.** The scene graph is C++ and an item has to be a C++ vtable,
so some C++ is unavoidable. Keeping it to a shim that calls `rv_ui_*` functions means the
shared core stays Qt-free and the workspace's `unsafe_code = forbid` holds everywhere but
`bridge/`. cxx-qt was the runner-up; qmetaobject-rs is Qt 5 era and passively maintained.

**The package ships a baseline plugin generation.** `pacman -S retrovert` must play something
offline. The PKGBUILD installs the signed channel artifacts under `/usr/lib/retrovert/plugins/`
as generation zero; the catalog's updater layers newer generations over it in the user's
data directory and falls back to the baseline when nothing else loads. Not built yet.

## Build and run

```
./build.sh                                  # release; ./build.sh debug for a dev profile of the bridge
./run.sh --plugins DIR song.hvl             # DIR holds decoder .so files
./run.sh                                    # no song: the scopes show a synthetic waveform
./run.sh --renderer opengl song.hvl         # skip the Vulkan probe
```

`retrovert-gui` is the whole command-line surface. Quickshell owns `main()` and refuses any
argument it does not know, so the launcher is what turns `retrovert-gui song.hvl` into a shell
that plays it: it finds `shell.qml` and the built `Retrovert` module (packaged paths first, then
this dev tree), picks the renderer, and execs `qs` with the song, plugin directory and import
path in `RETROVERT_*` variables. Those are a private channel to `ui/shell.qml`, never something
a user sets. The renderer rule is Flea's: an explicit `--renderer` or `QSG_RHI_BACKEND` is kept;
otherwise `launcher/src/vulkan.rs` asks the loader for an instance with Qt's surface extensions
and a device, and a refusal starts the shell on OpenGL with the reason printed once. A scene-graph
failure after launch relaunches once on OpenGL, only when the launcher made the choice.

Requires `qt6-declarative`, `cmake`, `alsa-lib` and a Rust toolchain. `bridge/include/retrovert_ui.h`
is generated by the bridge's build script and is what the shim compiles against.

Decoders must be built against the current `retrovert_api` headers: a plugin from before the
visualization ABI loads and then faults inside capture. Build one from `playback_plugins`, for
example `cmake -S plugins/hively -B build-hively -G Ninja && cmake --build build-hively`, and pass
its `plugins/` directory. `cargo run -p retrovert-ui-bridge --example probe -- DIR SONG` mounts a
song outside the shell and prints the layout and scope counts, which is the first thing to run
when the window says no plugin accepted the media.

## How playback runs

`bridge/src/engine.rs` is the desktop player's audio worker moved into the shell process: one
thread owns the `PlayerBackend` and the cpal stream, decodes every 2 ms, and sixty times a second
captures a `VizSnapshot`, refills its own `ScopeTrace`s and copies their points into a shared
front under a lock held for that memcpy alone. The render thread copies out of the same front in
`updatePaintNode`. `Session` polls the front's frame counter at 8 ms and raises `frame` only when
a new capture landed, so an idle song costs no repaints.

Decoding is paced to the wall clock, not to the ring. A decoder's scope is the audio it mixed
last, so the picture moves only when the decoder does; refilling the ring only when the device
callback drained it meant one 2048-frame burst about 24 times a second, and the scopes jumped at
that rate. The worker now earns frames at the sample rate and renders that many per loop, so
the ring hovers just under its 0.2 s target and every capture sees fresh samples. The ring is
refilled at full speed only below a quarter of its depth: at mount and after a stall. The
remaining ceiling is the decoder's: hively mixes in 50 Hz tracker ticks of 960 frames and writes
its scope buffer while mixing, so the scopes change 50 times a second, not 60. Mixing per
`read_data` request instead of per tick is a plugin change, if it is ever wanted.

`Session` is built when its QML component completes, not when `running` is set, because the
worker loads its decoders at construction and QML assigns initial properties in no fixed order:
built earlier, it would load from an empty `pluginDir`.
